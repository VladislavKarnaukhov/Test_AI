# Del Health — правила проекта

Бренд: **Del Health** (пишется именно так: не DEL HEALTH, не DelHealth). Прежние названия VitaScore и Adelina Health в интерфейсе недопустимы. Внутренние имена (БД instance/vitascore.db, cookie vs_*, переменные, файлы) не переименовывать. Контекст продукта — PRODUCT.md.

## Стек
- Python 3.11+, Flask, SQLite через стандартный модуль sqlite3 (без ORM).
- Фронтенд: чистые HTML/CSS/JS, без фреймворков и сборки.
- Зависимости только: Flask, pytest (и gunicorn для деплоя). Новые библиотеки — только с моего согласия.

## Ограничения
- Авторизация — только своя, по e-mail и паролю (app/auth.py). НЕ добавлять OAuth, сторонние API и новые внешние сервисы.
- Все POST-формы — с csrf_token; страницы кабинета — через @login_required; данные клиента выбирать только по g.user["id"].
- Яндекс.Метрику и виджет aistudio.yandexcloud не менять, кроме одного: Метрика и собственный лог событий
  включаются только после согласия на аналитические cookie (cookie vs_consent=all, см. app/consent.py).
- Новые cookie, трекеры и поля с персональными данными — только вместе с обновлением app/templates/privacy.html
  и POLICY_VERSION в app/consent.py.
- Ответы анкеты — данные о здоровье: /api/score без health_consent=true не считает и не хранит.
- Соглашения: /terms (TERMS_VERSION), /consent/health и /privacy (POLICY_VERSION) в app/consent.py; реквизиты
  оператора — только в app/templates/_operator.html. Новые данные о здоровье — вместе с текстом /consent/health.
- Красные флаги показывать всегда (не прятать за тарифом); формулировки — «обсудите со специалистом», не диагноз.

## Структура
- app/scoring.py — скоринг по методике docs/methodology-v2.0.md (три вложенных уровня: короткий/ядро, средний,
  расширенный), без импорта Flask. Единственный источник вопросов, условий показа, таблиц баллов, флагов и шагов:
  анкета на главной и страница /methodology строятся из него. Любая правка вопросов, баллов, весов или порогов —
  только вместе с METHOD_VERSION и docs/. Вопросы короткого уровня не менять — на них держится сравнимость ядра.
- Опросники с лицензией (LICENSED_INSTRUMENTS: SCI, STOP-Bang, MEPA) не включать без письменного разрешения.
- app/scoring_v1.py, app/scoring_v0.py — прежние версии, только для показа старых результатов. Не менять.
- app/results.py — сохранённая оценка → данные для страниц (все версии методики).
- app/db.py — подключение к SQLite, создание таблиц и миграции (_migrate).
- app/consent.py — cookie согласия и версия политики.
- app/visitor.py — разбор User-Agent, примерная страна, источник перехода; без Flask и без сторонних библиотек.
- app/routes.py — страницы и API.
- app/auth.py — регистрация, вход, CSRF, лимит попыток. Гостевые расчёты к аккаунту НЕ привязывать — только сделанные после входа.
- app/account.py и static/js/account.js — личный кабинет: интерактивная история, рекомендации, профиль, удаление.
- app/templates/, app/static/css/, app/static/js/ — фронтенд. CSS в трёх файлах, подключаются по порядку: base.css → components.css → pages.css. Новое правило пишется в нужный файл рядом с родственными (по семейству класса), а не «поверх» в конец; переопределение собственных правил дописыванием в конец запрещено — правьте исходное правило.
- tools/ui_audit.py — аудит наложений текста/выхода за край (python tools/ui_audit.py; нужен Chrome и запущенный сервер на :5050). Прогонять после любых правок вёрстки.
- tests/ — pytest.
- index.html, 404.html в корне — только редирект со старого GitHub Pages на новый адрес, не часть приложения.

## Команды
- Запуск: python run.py  (http://localhost:5000)
- Тесты: pytest -q
- Отчёты: sqlite3 instance/vitascore.db < reports.sql

## КРИТИЧНАЯ ЛОГИКА (не трогать при дизайн-работах)
app/scoring.py, scoring_v1.py, scoring_v0.py, results.py, consent.py, API /api/score, схема БД. Дизайн-задачи меняют только шаблоны, CSS, JS-отображение. Проверка: pytest + сравнение golden-снимка расчётов до/после.

## Дизайн
- Скиллы: Impeccable (audit/critique/polish, `impeccable detect`), design-taste-frontend (направление), animate (осмысленные микро-взаимодействия). Использовать при любой дизайн-работе.
- Принципы: premium, calm, human, scientific, minimal, editorial; уровень полировки Apple/Shopify. Первый экран — полноэкранное фото человека и один сильный заголовок; каждая секция имеет свою композицию.
- Избегать: generic SaaS, сетки одинаковых карточек, лишние градиенты, emoji, дешёвый сток, визуальный шум, лишние рамки и тени, нестабильные отступы.
- Типографика: один шрифт Inter (self-hosted, app/static/fonts, Cyrillic + Latin). Иерархия Display → H1 → H2 → H3 → body → caption; заголовки вес 500, плотный трекинг (−.04…−.05em); длина строки ≤ 34rem для лидов.
- Цвет: тёплый белый фон (#FAF8F4), угольный текст (#1F1E1B), один зелёный акцент (#2F6B4C), янтарный только для «главного потенциала» и предупреждений. Все значения — токены в начале base.css.
- Индекс (Health Score) — главный объект: кольцо `.ring-score` / `.score[style*="--v"]` + большое число; затем вклад сфер, затем один шаг. ДАННЫЕ → ОБЪЯСНЕНИЕ → ДЕЙСТВИЕ.
- Фото: app/static/img (WebP, `<picture>` + srcset, lazy кроме первого экрана), только Unsplash с бесплатной лицензией (не Unsplash+); источники — docs/IMAGES.md. Без медицинского стока.
- Mobile: iPhone-first (проверять 375 / 390 / 393 / 430 и 1440). Компактная шапка с меню на `<details>`, цели касания ≥ 44px, главный CTA в нижней половине экрана, safe-area, без горизонтальной прокрутки. На ≤600px первый экран: фото сверху, текст ниже.
- Анкета: один вопрос на экране (`.q-off` скрывает остальные; логика показа и расчёта не менялась), прогресс «Вопрос X из N».
- Анимация: transform/opacity/stroke и scroll-driven reveal; вход первого экрана ступенями (60–80 мс), набор длины полосок и счёт чисел при появлении на экране (JS, класс `js-motion`), мягкое раскрытие FAQ и истории (`::details-content`), переходы между страницами (`@view-transition`). Всё только в `@media (prefers-reduced-motion: no-preference)`; ease-out cubic-bezier(.23,1,.32,1); hover-эффекты только для мыши; ничего бесконечного. Счётчики ограничивать прогрессом 0–1.
- Доступность: WCAG AA, видимый фокус, skip-link, aria-live для результата, alt у всех фото, цвет не единственный носитель смысла.
- Правила UI: без новых библиотек и CDN; без слогана без согласования; не выдумывать отзывы, клиентов, регалии. `data-*` и id в шаблонах — хуки JS и тестов, не переименовывать. Метрика 113394370 и `data-metric` сохранять.
- Профиль и результат: на главной нет разбивки «что влияет на индекс» (только кольцо, статус и шаг; разбивка по сферам есть на экране результата и в кабинете). В кабинете история открывается по запросу: сферы, вложенные «Что вы ответили» и «Полный результат и советы», «Удалить оценку» (двухшаговое подтверждение, POST /account/results/<id>/delete, только свои записи, CSRF). Перед сдачей прогонять аудит наложений текста на 320–1440 px.
